# tweets

Feed service for the omono Feed tab. Scrapes location-tagged tweets
from `x.com`, biases ranking toward events / registration / festivals,
filters out spam, caches in SQLite, and exposes a small JSON API the
Android client polls.

## Architecture

```
   ┌──────────────────────────────┐
   │ tweets-browser.service       │   headless Chrome (1)
   │   /srv/tweets/browser-profile│
   │   CDP @ 127.0.0.1:9222       │
   └──────────────┬───────────────┘
                  │ CDP
   ┌──────────────▼───────────────┐
   │ refresh-template.py (2)      │   spawned by tweetsd hourly +
   │   writes /srv/tweets/        │   on auth failure
   │     cookies.json             │
   │     search-template.json     │
   └──────────────┬───────────────┘
                  │ files
   ┌──────────────▼───────────────┐
   │ tweets.service (3)           │   Go scraper
   │   reads cookies + template,  │
   │   hits SearchTimeline GQL,   │
   │   filters spam, scores events│
   │   writes SQLite cache        │
   └──────────────┬───────────────┘
                  │ HTTP
   ┌──────────────▼───────────────┐
   │ nginx tweets.omarss.net (4)  │   TLS terminator,
   │   /healthz, /tweets only     │   30s edge cache on /tweets
   └──────────────┬───────────────┘
                  │ HTTPS
              omono APK
```

1. **`tweets-browser.service`** — headless Chrome anchored to one
   X session, persistent profile at `/srv/tweets/browser-profile/`.
   Holds the authenticated cookies and is the only source of the
   `x-client-transaction-id` header that X's anti-bot gateway
   requires on every GraphQL call.
2. **`refresh-template.py`** — small Python CDP client that drives
   the headless Chrome through one search per refresh cycle and
   captures the resulting request URL + headers + cookies into
   two state files. Invoked hourly by tweetsd, and on demand
   whenever the scraper sees `401/403/404` (= session went stale).
3. **`tweetsd`** — Go service. Loads the state files, replays the
   captured `SearchTimeline` GraphQL call with our own `rawQuery`
   (`place_country:SA -is:retweet -filter:replies` for KSA, `:EG`
   for Egypt), scores each tweet for spam + event-relevance, and
   upserts into a SQLite cache. The HTTP handler reads from the
   cache (never blocks on Twitter).
4. **`tweets.omarss.net`** — nginx vhost that exposes only
   `GET /healthz` and `GET /tweets` to the public, with a 30 s
   edge cache.

## Why this design

X has spent the last 18 months killing scraping libraries. v1.1 API
endpoints are gone (404). Public GraphQL endpoints reject every
request without a fresh `x-client-transaction-id` signature, which
is generated by X's own JS in the browser bundle. Static-cookie
libraries (`imperatrona/twitter-scraper`) get authenticated 401s
because the signature isn't there.

A server-resident Chrome gives us the signature for free. Everything
else (the scraping, the spam/event filtering, the cache, the HTTP
API) stays pure Go.

## Endpoints

```
GET /tweets?country=ksa|eg
200 application/json

{
  "country": "ksa",
  "generated_at": "2026-05-25T15:55:00Z",
  "tweets": [
    {
      "id": "1797123456789012345",
      "author": "هيئة الترفيه",
      "handle": "GEA_SA",
      "text": "...",
      "created_at": "2026-05-25T15:35:00Z",
      "lang": "ar",
      "place": "Riyadh, Saudi Arabia",
      "country": "ksa",
      "reply_count": 142,
      "like_count": 2103,
      "retweet_count": 587,
      "spam_score": 0.0,
      "event_score": 0.85,
      "event_categories": ["festival", "registration", "schedule"]
    }
  ]
}

GET /healthz   →  {"status":"ok"}
```

- `country` optional; defaults to `ksa`. Anything other than `ksa` /
  `eg` returns `400 unknown country`.
- `spam_score` in `[0, 1]`. The service drops anything above
  `TWEETS_SPAM_THRESHOLD` (default `0.5`) before serving.
- `event_score` in `[0, 1]` from `internal/events`. Captures
  ticket/registration/concert/festival/conference/workshop/sports/
  talk/opening signals (Arabic + English vocabulary). The feed
  sorts on this descending so events float to the top while
  general location-tagged chatter is still visible.
- `event_categories` names which of those buckets matched, so the
  UI can render a small badge per row.
- When the SQLite cache is empty (fresh deploy, missing cookies,
  scrape failure with no prior batches), the handler falls back
  to a small hand-crafted fixture set so the UI is never blank.

## Cookie + signature lifecycle

You log into x.com **once** through a headed Chrome the Makefile
target opens — using the same profile dir the systemd service later
runs headless. From X's perspective, all login + scrape traffic
shares one IP, so the session-anomaly heuristic that invalidates
"cookies used from a server" never fires.

After that:

- `tweets-browser.service` runs the same profile headless 24/7.
- `tweetsd` invokes `refresh-template.py` **once an hour** (and on
  demand from auth failures) to capture a fresh
  `x-client-transaction-id` + cookie jar.
- The Go scraper does the actual 10-minute search cycles via direct
  HTTP using those cached files.

If you ever see `tweets.service` log `twitter auth rejected`, run
`make -C homelab tweets-refresh` manually.

## Configuration

| Flag / env | Default | Notes |
|---|---|---|
| `-addr` / `TWEETS_ADDR` | `:8080` | Listen address. `127.0.0.1:8088` in production. |
| `-cookies` / `TWEETS_COOKIES_PATH` | `/srv/tweets/cookies.json` | Full cookie jar JSON (incl. HttpOnly). |
| `-template` / `TWEETS_TEMPLATE_PATH` | `/srv/tweets/search-template.json` | URL + headers captured by the refresher. |
| `-db` / `TWEETS_DB_PATH` | `/srv/tweets/tweets.sqlite` | SQLite cache file. |
| `-interval` / `TWEETS_REFRESH_INTERVAL` | `10m` | Scrape cadence per country. |
| `-auth-refresh-every` / `TWEETS_AUTH_REFRESH_EVERY` | `1h` | Preemptive CDP refresh cadence. |
| `-spam-threshold` / `TWEETS_SPAM_THRESHOLD` | `0.5` | Drop tweets scoring above this. |
| `-readonly` | `false` | Skip scrape loop entirely; serve cache + fixtures only. |

## Layout

```
cmd/tweetsd/             entrypoint, flag parsing, graceful shutdown
internal/server/         HTTP routes + wire types + CachedSource
                         (store-with-fixture-fallback) + handler
internal/scrape/         HTTPScraper, state loader, response parser.
                         Direct GraphQL calls to /i/api/graphql/.../
                         SearchTimeline using cookies + template
                         captured by the refresher.
internal/refresh/        Wraps the python CDP script as a Go
                         AuthRefresher.
internal/events/         Event-keyword vocabulary + scoring.
                         Arabic + English: ticket / registration /
                         concert / festival / conference / workshop /
                         sports / talk / opening / schedule / venue.
internal/spam/           Heuristic spam scorer (links, hashtags,
                         mentions, emoji density, all-caps, account
                         age, follower ratio, duplicate-recent).
internal/store/          SQLite (pure-Go modernc driver), upsert
                         batch + latest-by-country + retention purge.
internal/feed/           Background refresh loop; ties scraper → spam
                         → events → store, plus auth-refresh trigger.
scripts/refresh-template.py   CDP client that drives the headless
                              Chrome and writes the state files.
```

## Local development

The service runs without cookies or Chrome in `-readonly` mode — it
serves the SQLite cache (or fixtures if empty). Useful for working
on the wire format / store / sorting without touching X.

```
make build
./bin/tweetsd -readonly -addr :18080 -db /tmp/dev-tweets.sqlite
curl 'http://127.0.0.1:18080/tweets?country=eg' | jq .
```

## Deployment

```bash
# 1. Provision both systemd units, build tweetsd, set up venv.
sudo make -C homelab apply-tweets-host

# 2. One-time login. Opens a HEADED Chrome with the systemd unit's
#    profile dir. Log into x.com (incl. 2FA / captcha if asked),
#    then close the window. The headless service inherits the session.
make -C homelab tweets-browser-login

# 3. Capture initial cookies + search template.
make -C homelab tweets-refresh

# 4. TLS — first run only.
sudo certbot --nginx -d tweets.omarss.net

# 5. Verify.
make -C homelab tweets-status
curl -sS https://tweets.omarss.net/tweets?country=ksa | jq '.tweets[0]'
```

After updates (`git pull`), re-run `sudo make -C homelab apply-tweets-host`
— idempotent, rebuilds the binary, restarts services.

## Make targets (homelab/Makefile)

| Target | What |
|---|---|
| `apply-tweets-host` | Provision everything (build binary + install both systemd units + nginx + venv). |
| `tweets-browser-login` | Open a headed Chrome on the systemd profile for one-time X login. |
| `tweets-refresh` | Trigger the CDP refresher manually and restart tweets.service. |
| `tweets-status` | Both unit statuses + local healthz probe. |
| `tweets-restart` | Restart browser + scraper (browser first). |
| `tweets-cookies-edit` | `sudo -e` /srv/tweets/cookies.json (rare; usually use refresh). |

## Risk acknowledgement

Scraping any way you slice it violates X's ToS. This design minimises
the behavioural signals X uses to detect bots — single source IP for
both login + scrape, sub-1 RPM cumulative load, no follow/like/post
operations — but **account suspension is non-zero risk**. Use a main
account at your own discretion; a throwaway is safer at the cost of
periodic re-login when X kills it. The session cookies allow the
scraper to read the feed and nothing else: the wrapper exposes Search
only; no write endpoint is ever called.
